P1宽度没有上限

叠加窗 SizeToContent=WidthAndHeight，RootPanel 与每行都没有 MaxWidth。内容多宽，窗口就多宽——不是被裁掉，而是直接画到窗口外面。

P2遥修拼成一句

GetRows 把 护盾 / 装甲 / 结构 各一层，同一行里重复「遥修」。3 层就是三份「遥修 … HP/s」，6 层（含输出）最长。

P3没有层级

分类、数值、单位、速率同一字号同一颜色，12 个分类长得一模一样。扫一眼只能「读完」，不能「瞟到」。

P4长分类名

「远程感应抑阻器」7 字、「停滞缠绕光束」6 字，在 12 DIP 下就是 84 / 72 DIP 纯名字，还没算数值。

P5预警和战斗「各说各话」

频道预警是两条整行文本、战斗是另一叠整行文本：两条预警的内容只有几十 DIP 宽，却各占一整条黑底； 更麻烦的是两块共用同一套字号 / 文字色 / 背景色，看起来像同一种信息——扫读时分不清哪行是情报、哪行是我在挨打。 而且预警没有自己的结构（跳数、几分钟前、最近 / 最新全糊在一句话里）。

纵向同样失控：2 行预警 + 12 个战斗分类全开按行堆叠约 14 × 24 = 336 DIP，在 270 高的预览窗里会盖掉整块画面。 新设计把高度也钉住——预警 1 行 + 状态 1 行 + 数值 1–3 行，最多约 110 DIP。

测量同一段遥修文本，在不同窗口尺寸下的实际行宽

字号按「预警文字字号 30 × 窗口宽 / 960，下限 12」推导；行宽 = 文本 + 两侧 padding 12；再和窗口宽度比。

02

五条设计原则

先定不变量，再谈样式

1恒不溢出

宽度由窗口决定，不由内容决定：叠加层宽度 = 预览窗客户区 − 12。任何一枚胶囊都不能把它撑宽；放不下就换行、再放不下就折叠。

2一眼分级

用形状分「状态 / 数值」、用字号分「分类 / 主值 / 速率」、用颜色分「受损 / 受益 / 电子战」。不靠读完一句话才明白。

3与日志监控同构

圆角、内边距、字号语法与「分类 + 数量 + 单位/速率」的写法都与日志监控一致；整块叠加层共用用户配色，画面上只有胶囊自己的底色。

4跟随用户字号

整块以「预警文字字号」为唯一基准等比缩放（含跟随窗口缩放与倍率），并给每级字号设下限；窗口小到 320 时自动进紧凑档，而不是缩成看不清。

5预警也在同一套语法里

频道预警不再是一行自由文本，而是「标签 + 跳数 + 分钟」的胶囊：标签说明这是最近还是最新，跳数是主值（越大字越显眼），分钟是新鲜度。它和战斗胶囊共用同一个宽度上限、同一个字号基准与同一套用户配色，外形也一致；标签与跳数让「情报」和「战斗」一眼可分。

07

行为规范

实现与验收都按这 13 条
R01

宽度夹在窗口内

MaxContentWidth = 预览窗客户区宽 / DPI − 12 − 2 × 边框；底板、每一枚胶囊、角色名徽章都受它约束。任何 provider 都不能把叠加窗撑宽。

R02

三段式：预警 → 状态 → 数值

一块底板内三个 zone，各自换行、互不挤压：预警（1 行，最多 2 枚）→ 状态（1 行，最多 7 枚）→ 数值（1–3 行）。顺序就是重要顺序：先看「周围有没有人」，再看「我能不能跑」，最后看「我还能撑多久」。

R03

预警胶囊

标签（最近 / 最新 / 最近最新）+ 跳数主值 + 「跳 · Nmin」；配色与战斗胶囊共用「叠加层样式」的文字色 / 背景色，底色 alpha = 0 时一起退化为描边胶囊（阶段 383）。最近与最新指向同一星系时合并成一枚。降级（Downgraded）整枚 55% 不透明，不消失。

R04

行数预算与折叠

数值区默认最多 2 行（设置可 1–3），超出折叠成 +N；伤害永不折叠。状态行、预警行各固定 1 行，放不下时从优先级最低的开始折叠（其他 → 抑阻 → 扰断 → 标记 → 网子 → ECM → 反跳；预警先折「最新」）。悬停看全部。

R05

紧凑档

可用宽 < 340 或基准字号 < 12.5 时：隐藏速率段（保留单位）、隐藏遥修微条、内边距 −1、间距 4 → 3。不缩小字号（有下限）；预警胶囊不降级（它本来就只有三个词）。

R06

遥修聚合

主值 = 各层最近值之和；速率 = 各层速率之和；微条 = 各层速率占比（盾 / 甲 / 构）。单层不画微条；各层明细进悬停。0 值层不出段。

R07

字号阶梯

基准 = 预警文字字号（跟随缩放，下限 12）。分类/标签 0.78×、主值 1.13×、单位/速率 0.66×、状态 0.73×，各自有下限（10 / 12 / 9.5 / 9.5）。预警的跳数用主值档，标签与分钟用 0.66× 档。

R08

空状态与开关

三段都没有可见胶囊就整块不渲染（不是空底板、不是「无战斗」占位）；只有预警时只画预警那一行，只有战斗时只画战斗两段——「显示频道预警」与「显示战斗信息」两个总开关互相独立。日志监控命中行（默认关闭、低频）暂保留旧文本行模板，不在本次胶囊化范围内。

R09

悬停详情

沿用现有聚合 ToolTip，判定矩形改为底板实际矩形；浮层不改变 HUD 尺寸。顺序与胶囊一致：预警（系统 · 跳数 · 时间 / 频道 · 发言人 · 原文）→ 状态/数值（分类 · 装备 · 来源 (舰船) · 数值/间隔 · 时间）。

R10

动画

新胶囊 120 ms 淡入 + 上移 1 DIP；数值不做滚动/计数；系统「减少动画」时全部关闭。HUD 不闪烁、不脉冲。

R11

过期

战斗行只显示未过期的（沿用现状）；反跳 / 干扰等 sticky 状态不受过期影响，直到清除或停止监控。预警不设过期——由 IntelWindow 的解除 / 降级机制决定它还在不在。

R12

设置语义：一套配色，两种标识

叠加层样式（字体 / 字号 / 跟随缩放 / 缩放倍率 / 文字颜色 / 背景色）同时作用于预警胶囊与战斗胶囊，字号也是整块 HUD 的基准（名字另有独立设置）。胶囊外观与日志监控小窗的战斗胶囊一致：圆角 10、内边距 8×2、无边框、同字号；不再额外画底板，画面上只有胶囊自己的底色。

R13

主题与对比

胶囊文字 / 底色由用户指定，不做自动反差（沿用现状）；底色全透明时补一圈文字色描边，避免只剩文字。

08

落到 WPF：改哪里

契约扩展 + 视图排版 + 一处宽度传递

默认行为零破坏：PreviewOverlayItem 新增的 Chip 为 null 时仍走旧的文本行模板（日志监控命中行不动）。 预警与战斗各自由 provider 输出结构化胶囊，排版与折叠放在 PreviewNameOverlayWindow——因为只有视图知道真实可用宽度。

验收清单

OverlayProbe 可断言的部分
宽度不溢出：320 / 480 / 640 三档下，叠加层 ActualWidth ≤ 客户区宽 − 12，含 12 个分类全开 + 遥修 6 层。
行数预算：数值区预算 1/2/3 时占用行数分别不超过 1/2/3；状态行恒为 1 行；折叠数 = +N 中的 N。
伤害永不折叠：任何预算与宽度下伤害胶囊可见；状态行超过 1 行时从优先级最低的开始折叠。
遥修聚合：主值 = 三层之和，微条比例 = 各层速率占比（±0.02），单层时不渲染微条。
字号阶梯：基准 12 / 15 / 18 时，label / value / meta 的实际字号符合 0.78 / 1.13 / 0.66 且不低于下限。
空状态：无行时底板 Visibility=Collapsed，叠加窗只剩名字（高度回到基线）。
三段顺序：预警 → 状态 → 数值；预警 / 状态各 1 行，只有预警时不留空行、不占战斗位置。
预警胶囊：标签 / 跳数 / 分钟正确；最近与最新同星系时合并成一枚；降级整枚 0.55 不透明。
预警配色：跟随用户的预警文字色 / 背景色；底色 alpha = 0 时退化为描边胶囊（仍可见）。
悬停不跳变：展开 / 收起 ToolTip 前后，叠加窗宽高不变（沿用阶段 356 断言）；详情顺序与胶囊一致。
紧凑档：320 宽下不出现速率段与微条，胶囊高度与间距按紧凑档缩小；预警胶囊不降级。
主题与性能：战斗色取自主题资源；1 秒心跳只在可见集合变化时刷新，折叠不在心跳里重排。
设置：全局关 / 单项关 / 未启动战斗日志 / 可显示四态徽标语义不变。
已知限制：网子 / 感应抑阻 / 武器扰断 / 目标标记没有日志行（客户端只画图标），因此 HUD 上不会出现—— 这不是本设计的取舍，是数据源边界（见阶段 357 记录）。不要为了「看起来完整」给它们造假数据。
