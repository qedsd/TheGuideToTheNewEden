现在的问题

扁平缩进树把「材料层级」讲清楚了，但没有回答排产问题：节点多时要翻很久，节点之间只有缩进关系， 看不到谁占用哪条线、什么时候释放、哪个节点在等料，也无法判断每个角色的 1–11 条槽是否够用。

结果页真正要回答的是下面四个问题，而不是「BOM 有多深」。

01谁做？哪个角色、哪条产线？
02什么时候开始 / 结束？能不能并行？
03这个节点要什么投入、产出给谁？
04瓶颈在哪？哪些料要买、哪些库存能抵？

设计立场

把「产线」当一等资源，把「时间」当主轴，把「物料流」当关系，把「采购缺口」当常驻状态。 不是把树画得更漂亮，而是把计划变成一张可以操作的排产板。

产能来自技能：制造 / 发明 / 反应槽位各 1–11，总产能 = Σ 角色槽位；技能还改变同一任务的耗时，所以分工是优化结果，不是固定标签。

1产线 / 时间是第一信息，不能藏在节点详情里。
2选中即聚焦：只保留直接上下游，其余淡出。
3语义缩放：节点多时折叠成组，放大再展开细节。
4可操作：拖拽改派、自动排产、瓶颈告警，而不是只读图表。

3共用数据层：同一份 schedule 模型，角色数量变化时只改变分组，不重写视图。

贯穿五种方案的原则

01产线是一等资源：制造 / 发明 / 反应槽位各 1–11，由技能决定；总产能 = Σ 角色槽位，不再只是节点文本。
02时间是主轴：甘特条、时间带、完成时刻必须在第一屏。
03颜色表达活动：制造青 / 发明紫 / 反应橙 / 采购灰 / 关键红。
04焦点 + 上下文：选中只留直接上下游，其余淡出，避免全局线团。
05语义缩放：节点多时折叠成组，放大再展开，不要一次画完。
06物料平衡常驻：缺口、库存、采购金额和告警不藏进二级页。
07物料明细与排程同级：步骤页签列出每一步产出 / 投入，右栏只负责选中项详情。
08技能同时改变耗时：同一任务在不同角色上的 duration 不同，分配要比最早完成 / 成本，而不是只看谁空着。
