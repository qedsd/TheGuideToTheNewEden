# 商业 · 倒货

## 一句话 {#tldr}
在**源市场**低价买入、到**目的市场**高价卖出之前，先用两侧的真实订单与历史统计筛一遍：勾出**目标物品**，先「获取订单」取数，再「分析推荐」按**推荐度**排出值得倒的物品，并给出净利润、回报率、本金、日销量、饱和度、热力值、ISK/跳、ISK/单位体积等指标。

## 在哪打开 {#where}
- 左侧导航「**商业**」→「**倒货**」。
- 页面是三个页签的壳：**倒货** / **购物车** / **记录**。本篇只写「倒货」页签；购物车与记录见 [商业 · 倒货 · 购物车](scalper/cart) 与 [商业 · 倒货 · 记录](scalper/records)。
- 「倒货」页签本体分左右两栏：左栏是「**基本设置** / **进阶设置** / **排除列表**」三个页签，底部是「**获取订单**」「**分析推荐**」两个按钮；右栏是结果表。
- 取数 / 分析期间弹出**全屏等待遮罩**（居中卡片：旋转指示 + 实时文案；只有取数时带「**取消**」按钮），结束时右下角出现通知（成功给汇总、失败给原因、取消给「已取消」）；通知会自动消失，也可以点卡片上的 ✕ 立刻关掉。
- 结果表上**右键**→「**添加到购物车**」；**双击**一行→打开独立的「**倒货物品详情**」窗口。

## 前置条件 {#prereq}
- 星域 / 星系市场**不需要登录角色**；**建筑市场**需要该建筑已加入「设置 → 玩家建筑」，且有角色对它**有市场访问权**，否则订单取不到。
- 源市场、目的市场、目标物品三者缺一不可：缺哪项，点按钮时就给哪项的提示；「分析推荐」还要求结果表里已经有订单数据。
- 取数行为受「设置 → 市场」影响：「**倒货跳过公开建筑订单**」（默认开）与「**ESI查询线程数**」。倒货自己的设置存在独立存档里，与旧版共用同一份。

## 操作步骤 {#steps}

### 选源市场 / 目的市场
1. 「基本设置」顶部两行是「**源市场**」「**目的市场**」，各为一个按钮：未选时显示「未选择市场」，选中后显示所选市场名。
2. 点按钮弹出选择器，三个页签「**星域** / **星系** / **建筑**」，各带搜索框（「搜索星域」「搜索星系」「搜索建筑」）。
3. 点中一项即选中，弹层自动收起。

### 勾目标物品
1. 「**目标物品**」一行右侧实时显示已勾数量。
2. 下面是市场物品树：物品节点是复选框，分组节点是三态复选框，勾一个分组会连带勾上它下面的物品。
3. 顶部搜索框「**搜索市场物品**」：输入关键字后切换成搜索结果的勾选列表（点一行即切换那一项的勾选），清空关键字回到整棵树。
4. 源 / 目的市场与目标物品会在点「获取订单」时写入存档，下次进来自动恢复。

### 进阶设置（九个折叠项）
1. 自上而下依次是「**买入价格**」「**卖出价格**」「**源市场日销量**」「**目的市场日销量**」「**历史价格波动**」「**当前价格波动**」「**卖单饱和度**」「**热力值**」「**推荐值来源权重**」，逐项展开设置。
2. 「买入价格」「卖出价格」结构相同：**价格类型**下拉（十个口径）、**历史价格统计天数**、**价格缩放系数**（最小 0.1）、「**去极值**」勾选；其中「历史价格统计天数」与「去极值」只在价格类型选到四个「历史…」口径时出现，「价格缩放系数」始终可见。
3. 「源市场日销量」「目的市场日销量」：**统计历史天数**、**销量计算方式**（历史最低销量 / 历史最高销量 / 历史平均销量）、「**去极值**」；目的市场一侧另有一条**目标销量百分比**滑条（1–100）。
4. 「卖单饱和度」里是「**有效订单价格波动范围（%）**」；「热力值」里是「**历史价格天数**」与「**销量阈值**」。
5. 「推荐值来源权重」是九条 0–100 的滑条（回报率 / 目标销量净利润 / 本金 / 日销量 / 历史价格波动 / 当前价格波动 / 卖单饱和度 / 热力值 / ISK/单位体积），决定推荐度里各指标各占多少。
6. 本页**没有「保存」按钮**：点「获取订单」或「分析推荐」时会先把当前设置写入存档。

### 排除列表
1. 「**排除列表**」页签列出要从分析里剔除的物品。
2. 列表支持多选，选中后点底部「**删除选中**」把物品移出列表。
3. 被排除的物品在「获取订单」时就已从两侧订单里滤掉，不会出现在结果表里。

### 获取订单
1. 点「**获取订单**」，弹出等待遮罩，文案依次推进：「**获取源市场订单中**」→「**获取目的市场订单中**」→「**获取源市场订单历史中（已完成/总数）**」→「**获取目的市场订单历史中（已完成/总数）**」→「**匹配订单历史中**」；订单分页取数时文案形如「获取源市场订单中:已完成/总页数」。
2. 中途想停下就点遮罩里的「**取消**」：取数中止，右下角给一条「**已取消**」，缓存里**不会**留下半截结果。
3. 完成后右下角给一条汇总通知，形如「**已获取到{物品数}个有效物品订单(耗时：{分钟}分钟  错误：{n}  异常：{n}) 无历史记录：{n}(源市场) + {n}(目的市场)**」——报出有效物品数、耗时（分钟）、期间的错误与异常条数，以及两侧各有多少物品没有历史记录。
4. 结果表随后列出这些物品；推荐度等指标要等「分析推荐」才算出来。

### 分析推荐
1. 点「**分析推荐**」：出现等待遮罩（文案「**分析中**」），算完按**推荐度降序**重排结果表，右下角给「**分析完成: 条数**」。
2. 分析只重算指标，不重新取数；改完进阶设置后可以直接再点它，**排除列表的增删要重新点「获取订单」才会反映到结果里**。

### 看结果与后续
1. 结果表共 18 列，右侧的列需要横向滚动查看。
2. 选中一行或多行 → 右键 →「**添加到购物车**」，物品进入购物车页签。
3. 双击一行 → 打开「**倒货物品详情**」窗口：左侧是全部指标，右侧是「**源市场** / **目的市场**」两个页签，各有「**卖单** / **买单** / **历史**」；历史里再分「**价格**」与「**销量**」两个图，右上角时间范围可选「**最近1个月 / 最近3个月 / 最近半年 / 最近一年 / 全部**」（默认最近1个月）。同一时刻只保留一个详情窗，双击别的行会换成那一行。
4. 详情窗用的就是本次分析已取到的订单与历史，不再重新取数（只有物品图标是联网取的）。

## 字段与口径 {#fields}

| 列 / 设置 | 含义 | 口径 |
|---|---|---|
| 推荐度 | 综合排序分（0–100） | 各指标按排名加权累加后归一到百分比，是**相对分位**，只在本批结果内有意义 |
| 回报率(%) | 单位净利润相对买入价的比例 | 单位净利润 ÷ 源市场买入价格 × 100 |
| 目标销量净利润 | 按目标销量能赚到的钱 | 单位净利润 × 目标销量 |
| 源市场买入价格 / 目的市场卖出价格 | 两侧的单价 | 按「价格类型」算出后乘「价格缩放系数」；算不出所选口径时回落目的市场最近一天均价 |
| 源市场日销量 / 目的市场日销量 | 两侧每日成交量 | 按各自的统计天数、去极值方式与「销量计算方式」从历史统计取 |
| 目标销量 | 打算卖出的量 | 目的市场日销量 × 目标销量百分比（向上取整） |
| 单位净利润 | 单件利差 | 目的市场卖出价格 − 源市场买入价格 |
| 本金 | 投入的 ISK | 源市场买入价格 × 目标销量 |
| 历史价格波动 | 历史价的离散程度，越小越稳 | 区间内历史均价的标准差 ÷ 平均值 |
| 当前价格波动 | 现价偏离历史均价的程度 | 目的市场卖出价格与历史平均价之差的**绝对值** ÷ 历史平均价 |
| 卖单饱和度 | 目的市场挂单相对日销量的倍数 | 有效价格范围内的卖单量 ÷ 日销量 |
| 热力值 | 销量达标天数的净值 | 区间内逐日累加：日销量不低于销量阈值记 +1，否则记 −1 |
| 目标销量体积 | 这批货的总体积 | 物品打包体积 × 目标销量 |
| ISK/跳 | 每跳能赚多少 | 目标销量净利润 ÷ 源市场到目的市场的最短星门跳数 |
| ISK/单位体积 | 每立方米能赚多少 | 目标销量净利润 ÷ 目标销量体积 |
| 价格类型 | 取价口径 | 十个：卖单前5%最低价格订单平均价格 / 卖单实际数量的相应价格 / 卖单最低价格 / 买单前5%最高价格订单平均价格 / 买单实际数量的相应价格 / 买单最高价格 / 历史最高价格 / 历史平均价格 / 历史最低价格 / 历史中位数 |
| 去极值 | 历史统计的截尾方式 | 勾上后去掉极值再平均：价格历史去掉一个最大值，销量历史在数据多于 3 天时同时去掉最小与最大值 |
| 实际数量的相应价格 | 按量吃单的加权均价 | 按该侧日销量逐档吃单算出，而不是只看第一档价格 |

## AI 能替你做什么 {#ai}
- 工具：`scalper_settings`（只读，**无需确认**）报出源市场、目的市场、目标物品数与取数线程；`scalper_analyse`（**重型分析，执行前需要你确认**，取数是分钟级、大量 ESI 调用）按推荐度给前 N 条候选，参数为 `top`（默认 15、上限 30）、`minProfitIsk`、`minRoi`；`shopping_cart`（**写操作，需要你确认**）把物品加进购物车，价格由它从别的分析结果里取，工具自己不取价。
- `scalper_analyse` 用的是**页面上存下来的设置**：先在「商业 → 倒货」把源 / 目的市场与目标物品配好，AI 才有范围可分析；设置不全时它会明确拒绝并让你先去配置。
- 推荐问法：「倒货现在是什么配置」「现在有什么值得倒的」「回报率 20% 以上、净利润不低于 1 亿的有哪些」「把这几样加进倒货购物车」。
- **做不到**：不能替你改倒货设置（源 / 目的市场、目标物品、进阶设置、排除列表都只能在页面上改）；不能把分析结果铺到页面的结果表里（`scalper_analyse` 是独立跑一遍取数与计算，不写回本页）；也不返回订单明细，要明细请用市场类工具或双击进详情窗。
- AI 回答里的净利润、回报率、销量一律以工具数据为准，**不要采信对话里的旧数字**。

## 常见失败与处置 {#errors}

| 界面提示 | 原因 | 处置 |
|---|---|---|
| 请选择源市场 / 请选择目的市场 | 对应市场还没选 | 点按钮选星域 / 星系 / 建筑 |
| 请选择物品类型 | 目标物品一个都没勾 | 在物品树或搜索列表里勾上物品 |
| 请先获取订单 | 结果表还是空的就点了「分析推荐」 | 先点「获取订单」 |
| 获取源市场订单失败：{原因} / 获取目的市场订单失败：{原因} | 取数过程报错，常见是建筑无授权、ESI 限流或网络不通 | 按原因处理；建筑市场先确认「设置 → 玩家建筑」与角色的市场访问权；稍后重试 |
| 获取订单失败 | 某一侧过滤后订单为空 | 确认目标物品在两侧都有挂单，且排除列表没有把物品全滤掉 |
| 已取消 | 你在等待遮罩里点了「取消」 | 属预期；重来时重新点「获取订单」 |
| 获取源市场订单中:x/y 长时间不结束 | 整星域取数本就是分钟级 | 等待或点「取消」；换更小的市场范围并不会更快（见限制） |
| 汇总通知里的「无历史记录」不为 0 | 部分物品在对应市场没有历史统计 | 这些物品会被剔出分析，属正常 |

## 限制与已知问题 {#limits}
- **整星域取数是分钟级的大任务**：源市场选星域时会把整星域全量订单分页拉下来，再做两侧全物品历史；这是有意的重操作，在本页只在点「获取订单」时发生。
- **选「星系」并不更便宜**：星系口径会先拉整星域再按星系过滤，取数成本与星域相同（REFACTORING §8-22）。
- **建筑市场**：整栋建筑全量拉取、需要角色对该建筑有市场访问权，首次明显较慢；建筑的历史用的是**该建筑所在星域**的历史（REFACTORING §8-9）。
- **推荐度是相对排名**：它由本批结果的排名加权算出，改目标物品范围或改「推荐值来源权重」都会让分数整体变化，不能跨两次分析直接比大小。
- **计算引擎是旧版公式的逐条移植**，数值口径以旧版为准，未做逐项对拍（REFACTORING §8-18）。
- **「倒货跳过公开建筑订单」默认开**：开着时星域 / 星系取数不含只挂在这些建筑里的订单；关掉后每个建筑都要整栋拉一次，首次非常慢。
- **排除列表目前只有本页的移除入口**：市场页 / 订单页的倒货排除右键动作（旧版有）尚未接线，列表也不跨进程保存（REFACTORING §8-16、§8-21）。
- **全屏等待遮罩与右下角通知只接入了倒货页**：市场 / 订单等页面仍是页内文字提示（REFACTORING §8-4）；遮罩是应用级的，取数期间会挡住其它页面的操作。
- **目标物品与结果表的能力边界**：市场物品树是一次性全量构建，首次进入本页有短暂耗时（REFACTORING §8-12）；结果表只保留排序 / 列宽 / 列重排这类标准表格能力，没有分组、列筛选与分组合计（REFACTORING §8-3）。
- **分组复选框的三态语义**：点分组会在未选 → 全选 → 半选之间循环，停在半选时不再回写子项（与旧版一致，REFACTORING §8-23）。
- **物品详情窗未做实机核验**（REFACTORING §8-19）：首次打开若表格或图表为空，先确认这一步确实已经「获取订单」成功。
