# 疑难排查

## 一句话 {#tldr}
按现象找原因与处置：托盘建不出来、打开目录被拒、设置不生效、添加角色卡在授权、ESI 报权限不足、市场取不到数据——先对号入座，再按处置操作，最后到日志确认。

## 这份手册讲什么 / 从哪开始 {#where}
- 按**现象**组织，不按功能分页：各功能手册的「常见失败与处置」只收该功能内的报错，这里收**跨功能**的环境与授权问题。
- 从哪开始：在下方「常见失败与处置」对号入座。环境类（托盘 / 通知 / 打开目录 / 写入）多半与**运行位置**有关；授权类先跑「设置 → 测试 → 回环回调 → 检测」。
- 都对不上时看日志：位置见「位置速查」，拿当天文件里的 WARN / ERROR 行与本表现象对照。

## 排查流程 {#steps}
1. **先分环境还是功能**：托盘、通知、打开目录、写设置**同时**异常 → 基本是运行位置问题，走第 2 条；只有单个功能异常 → 去该功能手册的「常见失败与处置」。
2. **环境问题的处置**：把程序**复制**到普通安装位置（桌面或常规目录）再运行；不要把程序留在受限目录里跑，也不要手工改 exe 的完整性标签。
3. **授权问题**：「设置 → 测试 → 回环回调」点「检测」看是否「监听成功」；再核对 EVE 开发者后台登记的 Callback URL 与配置里的地址完全一致（卡片「复制」可直接取地址）。
4. **权限不足**：「设置 → 权限选择」勾上缺失的 scope，然后到「角色」页删除该角色、重新「添加角色」授权——勾选不影响已授权角色，必须重新授权才生效。
5. **还不行**：看当天日志（程序目录下 `Log` 文件夹）里的 WARN / ERROR 行；设置不生效类问题，确认配置目录可写。

## 位置速查 {#fields}

| 位置 | 内容 | 排查用途 |
|---|---|---|
| 软件日志：程序目录下 `Log` 子文件夹，按日期一个 `.txt` | 启动、异常与托盘 / 授权回调的诊断行 | 「设置 → 一般」的「App日志 → 查看」或主页「打开日志」直达；任何异常先看这里 |
| 配置目录 `%LocalAppData%\TheGuideToTheNewEden\Configs` | `settings.json`（设置）、`ESILicense.txt`（第 2 行 = 回调地址）、角色授权与市场缓存文件 | 「App配置文件 → 查看」或主页「打开配置目录」直达；设置不生效、回调地址不一致时核对这个目录 |
| EVE 游戏日志 | EVE 自己写的聊天 / 游戏日志 | 「设置 → 游戏日志」的路径（默认「文档\EVE\logs」）；频道类功能取不到数据时核对 |

## AI 能替你做什么 {#ai}
- **排查动作没有 AI 工具**：AI 不能替你点「检测」、改设置、重新授权或清缓存。
- AI 能帮的核对：问「我登录了哪些角色」（`character_list`）判断角色到底加没加上；AI 经 ESI 网关调用失败时会把**缺哪个 scope** 转述出来，并建议去「设置 → 权限选择」勾选后重新授权。
- 让 AI 用同一口径：把界面报错**原文**发给 AI 对照本表定位；结论以工具结果与日志为准，AI 查不到会明说。
- **做不到**：读不到你的游戏日志正文与系统日志；也不能替你重启软件。

## 常见失败与处置 {#errors}

### 环境与目录
| 现象 | 原因 | 处置 |
|---|---|---|
| 托盘里没有图标；开了「关闭窗口时最小化到托盘」，关窗口后程序却直接退出 | 运行位置的完整性级别低于系统要求，托盘图标创建被系统拒绝（常见于受限目录） | 把程序复制到普通安装位置运行；不要手工给 exe 设完整性标签。软件此时会退回"直接退出"，不会把窗口藏起来 |
| 通知发不出，「检测环境」显示「应用通知不支持」 | 托盘图标没创建成功，通知通道不可用 | 先按上一条处置，再回「设置 → 测试」重测 |
| 点「查看」这类打开目录的按钮失败，提示「无法打开（系统拒绝了请求；当前运行上下文受限）」 | 运行上下文受限，系统拒绝了打开目录的请求 | 随后会有「路径已复制到剪贴板，可粘贴到资源管理器打开」的提示，自己粘贴打开；或换普通位置运行 |
| 设置改动重启后丢失 | 配置目录只读或写入被系统拒绝（界面不报错） | 换普通安装位置运行，确认配置目录可写 |

### 授权与回调
| 现象 | 原因 | 处置 |
|---|---|---|
| 点「添加角色」弹「登录失败」 | 授权没成功，且没有更具体原因可显示 | 重试；「设置 → 测试 → 回环回调」点「检测」，确认地址与 EVE 开发者后台登记一致 |
| 「无法监听授权回调地址 …（端口可能已被占用）」 | 回调端口被其它程序占用 | 关掉占用该端口的程序后重试 |
| 「回调地址里没有 code 参数」 | 收到的回调网址不完整 | 重新走一次授权 |
| 「授权码校验失败（授权码可能已过期或已被使用）」 | 授权码已失效或被用过 | 重新授权，取一条新的网址 / code |
| 浏览器授权页直接报英文错误（提示 redirect_uri 不匹配） | 配置的回调地址与开发者后台登记的不一致 | 「回环回调 → 复制」取地址，把 `Configs/ESILicense.txt` 第 2 行与开发者后台登记值改成完全一致；不支持通配端口 |
| 「当前游戏服务器不是国服（Serenity）：请先到"设置 → 一般"把服务器切换为国服，再进行国服授权。」 | 在非国服下走国服向导 | 先切服务器，再重新走向导 |
| 「校验授权失败」（国服向导，下方附服务端错误详情） | 粘贴的内容不对，或当前服务器 / 凭据与目标服务器不一致 | 确认服务器是 Serenity；整条网址或纯 code 都可以粘，然后重新授权 |

### 数据与权限
| 现象 | 原因 | 处置 |
|---|---|---|
| 「结构解析失败：请确认已有授权角色，且勾选了 esi-universe.read_structures.v1 权限。」 | 角色授权时未包含该权限 | 「设置 → 权限选择」勾选后到「角色」页重新授权 |
| 「建筑订单获取失败：需要角色授权，且该角色对该建筑有市场访问权限」 | 没有角色、缺该 scope，或该角色对此建筑无市场访问权 | 确认建筑已加入「设置 → 玩家建筑」、已登录角色且有访问权；否则改用星域市场 |
| 「角色「XX」缺少该端点所需的权限：…。请到 设置 → 权限选择 勾选这些 scope，然后到「角色」页重新授权该角色。」 | AI 经 ESI 网关调用时发现角色缺 scope | 按提示勾选缺失项并重新授权 |
| 频道页里频道列表是空的 | 日志路径不对、最近 N 天没有频道文件，或游戏里没打开过频道 | 核对路径指向 EVE 的 logs 目录；调大「聊天频道文件有效天数」；进游戏打开一次目标频道 |
| 查市场历史第一次特别慢 | 历史未命中磁盘缓存 | 首次会写入缓存，之后变快；缓存时长在「设置 → 市场」调整 |

## 限制与已知问题 {#limits}
- **环境类失败根在"运行位置"**（REFACTORING §8-62）：受限目录里进程完整性过低，托盘、打开目录、写 `%LocalAppData%` 都可能被系统拒绝；把程序复制到普通目录运行即可。不要手工改 exe 的完整性标签——在 UAC 关闭的机器上，显式标签反而会把进程压到低于系统外壳、制造同类失败。
- **打开目录失败会优雅降级**（阶段 83）：不再弹系统错误框，而是把路径复制到剪贴板并给出应用内提示。
- **低完整性进程里写 EVE 客户端配置会被拒**（§8-63）：「配置同步」的写操作失败时按提示里的系统原因处理；正常使用请从普通安装位置运行。
- **欧服授权只走本地回环**（§8 环境/协作注意）：旧的自定义协议 / 注册表通道已删除，不要按旧资料配置；回调地址两处必须完全一致、不支持通配端口。
- **设置与旧版 WinUI 共用** `Configs/settings.json`（§8 环境/协作注意）：两版同时运行会互相覆盖，建议只保留一版。
