# 设置 · 软件更新

## 一句话 {#tldr}
检查有没有新版本、下载安装包并启动外部安装程序完成升级——应用自己不更新自己，「安装」这一步交给下载下来的安装器。

## 在哪打开 {#where}
- 左侧导航「**设置**」→ 分类列表「**软件更新**」（说明文案：「检查软件更新」）。
- 页面两张卡片：**当前版本**（右侧显示当前版本号）与**检查更新**（状态文字 + 「检查更新 / 下载 / 安装」三个按钮，后两个初始置灰）。
- 开启自动检查时，主页品牌条上会出现「**有新版本 ××**」提示胶囊，点它直达本页（提示文案「点击前往「设置 → 软件更新」」）。
- 也可在主页「添加功能」窗口里把「设置 · 软件更新」加成磁贴。

## 前置条件 {#prereq}
- 需要能访问网络：检查与下载都连 **GitHub** 发布页；内网 / 代理环境可能取不到。
- 「下载」只在该发布**附带安装包附件**时才可用。

## 操作步骤 {#steps}

### 手动检查与升级
1. 点「**检查更新**」→ 状态显示「**正在检查更新…**」。
2. 结果二选一：「**已是最新版本**」，或「**发现新版本 版本号**」且「**下载**」亮起。
3. 点「**下载**」→ 状态「**正在下载…**」，服务器报告总大小时会追加百分比；安装包下载到系统临时目录。
4. 下载完成 → 状态「**已下载完成，点击“安装”启动安装程序。**」，「**安装**」亮起。
5. 点「**安装**」→ 启动下载好的安装程序，由它接管升级（关闭旧版、写入新文件等按安装器提示走）；本应用不会自行替换文件或自动重启。
6. 安装启动失败会弹窗警告，处理后可重新点「安装」。

### 自动检查更新
1. 开关在「**设置 → 一般 → APP更新**」：勾选「**自动检查更新**」（默认开启）。
2. 开启时打开主页会静默检查一次：只有发现新版本才在主页显示提示胶囊；检查失败不弹窗、只记日志。
3. 关闭后只保留本页的手动「检查更新」。

## 字段与口径 {#fields}

| 项 | 含义 | 口径 |
|---|---|---|
| 当前版本 | 本机运行的版本号 | 取应用自身版本，比较时忽略后缀 |
| 发现新版本后的版本号 | GitHub 最新发布（tag）的版本号 | 去掉 tag 前缀 v/V 后与当前版本比较 |
| 下载百分比 | 已下载 / 总大小 | 服务器未返回总大小时只显示「正在下载…」 |

## AI 能替你做什么 {#ai}
- 本页**没有开放任何 AI 工具**：AI 不能检查更新、下载或安装，也读不到当前版本与检查结果。
- 推荐问法：「怎么更新到最新版」——AI 给出的是到本页操作的指引。
- **做不到**：不代下载、不代装；「安装」必须由你点击并按安装器提示完成。

## 常见失败与处置 {#errors}

| 界面提示 | 原因 | 处置 |
|---|---|---|
| 检查更新失败: 具体原因 | 网络不通，或 GitHub 匿名接口对本机限流（常见，稍后自动恢复） | 稍后重试；代理 / 内网环境先确认能访问 GitHub |
| 「下载」始终置灰 | 该发布没有可下载的安装包附件 | 到项目发布页手动获取安装包 |
| 状态停在「正在下载…」后报错 | 下载中断（网络波动） | 重新点「下载」；不支持断点续传，从头重来 |
| 安装时弹窗警告 | 安装器未能启动（文件被占用或被安全软件拦截） | 关闭应用后重试；检查安全软件隔离区 |

## 限制与已知问题 {#limits}
- **「安装」交外部更新器**（REFACTORING §8 计划内未做）：应用内只负责把安装包拉下来并启动它，没有安装进度、不会自动重启、不做静默升级。
- **检查走 GitHub 匿名接口**：匿名请求有限流配额，失败多见于配额耗尽（REFACTORING 阶段 92 已把这类失败降为普通日志，不算故障）；自动检查失败不会打扰你。
- **版本比较忽略后缀**：预发布 / 带构建后缀的版本号按主干数字比较，比较不出差异时按「已是最新版本」处理。
- **下载不暂停、不续传**：中断后需要重新下载。
