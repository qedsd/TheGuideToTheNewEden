# 设置 · 软件更新

## 一句话 {#tldr}
检查新版本，从 **Gitee 镜像 / GitHub** 下载单文件 exe（Gitee 大文件按 100 MB 以内分片），校验通过后由应用自己替换当前 exe 并重启——绿色版没有安装程序，也不需要外部更新器。

## 在哪打开 {#where}
- 左侧导航「**设置**」→ 分类列表「**软件更新**」（说明文案：「检查软件更新」）。
- 页面三张卡片与一个可展开的更新详情：
  - **当前版本**：右侧显示版本号；
  - **自动检查更新**：开关（与「设置 → 一般 → APP更新」是同一个设置）；
  - **检查更新**：状态文字 +「打开发布页 / 检查更新」两个按钮；
  - 发现新版本后出现**详情卡**：最新版本、发布日期、包大小、更新内容、下载进度，以及「停止 / 下载 / 安装并重启」。
- 开启自动检查时，主页标题右侧版本号旁会出现「**有新版本**」提示，点它直达本页。

## 前置条件 {#prereq}
- 需要能访问网络。**检查与下载优先走 Gitee**（国内可达性更好），失败自动回退 **GitHub**；两者都不通时只能手动下载。
- Gitee 发行版**单个附件上限 100 MB**（GVP 项目 200 MB），而单文件 exe 约 134 MB，所以发布方会把 exe 切成 `*.001`、`*.002` 等分片；应用下载后按顺序拼接并校验整包 SHA-256。
- **程序要放在当前用户可写的目录**：更新会改写 exe 本身。放在 `Program Files` 等受保护目录时，自动替换会失败，只能按提示去发布页手动覆盖。
- 发布方需要上传**单文件 exe**（Gitee 上是分片，GitHub 上是整包）以及 `update.json`；没有可用资产时只能「打开发布页」手动下载。

## 操作步骤 {#steps}

### 手动检查与升级
1. 点「**检查更新**」→ 状态显示「**正在检查更新…**」。
2. 结果三选一：
   - 「**已是最新版本**」；
   - 「**发现新版本 ××**」并展开详情卡 → 点「**下载**」；
   - 「**发现新版本 ××，但没有可用的下载源**」→ 点「**打开发布页**」手动下载。
3. 下载中会显示「正在从 **Gitee / GitHub** 下载…」、百分比、速度与进度条；此时「下载 / 安装」按钮会隐藏，只显示「**停止**」；点它可中止，已下载的部分保留，下次继续（**支持断点续传**）。某个源失败会自动换下一个源。
4. 下载完成 → 状态「**已下载并通过校验**」（大小、PE 头；发布方提供 SHA-256 时还校验整包哈希，分片各自也有校验）。
5. 点「**安装并重启**」→ 确认框里确认 → 应用关闭、用新 exe 替换本目录下的 exe，然后自动重启。
6. 若目录不可写或替换被拦截，会给出失败原因；旧版本会尽量保留，不会因为更新失败而无法启动。

### 自动检查更新
1. 开关在「**设置 → 一般 → APP更新**」或本页的「自动检查更新」卡片：勾选后默认开启。
2. 开启时启动/进入主页会静默检查一次（15 分钟内不重复请求）：只有发现新版本才在主页显示提示胶囊；检查失败不弹窗、只记日志。
3. 关闭后只保留本页的手动「检查更新」。

## 字段与口径 {#fields}

| 项 | 含义 | 口径 |
|---|---|---|
| 当前版本 | 本机运行的版本号 | 取应用自身版本，支持 `4.0.0-alpha.2` 这类预发布后缀 |
| 最新版本 | 发布版本号 | 去掉 tag 前缀 v/V；按语义化版本比较：`4.0.0 > 4.0.0-rc.1 > 4.0.0-beta.10 > 4.0.0-alpha.2` |
| 发布日期 / 大小 | 发布的发布时间与 exe 字节数 | 来自 `update.json` 或 GitHub API；缺失时显示为空 |
| 下载源 / 分片 | 这次从哪个镜像下载、是否分片 | Gitee 可能由多个 `*.001`/`*.002` 分片组成；按清单顺序拼接，整包大小与 SHA-256 校验 |
| 下载进度 | 已下载 / 总大小 | 服务器未报告总大小时只显示「正在下载…」；重连/换源后续传从已有字节继续 |
| 校验 | 下载完整性 | 文件大小 + `MZ` 头 +（发布方提供时）SHA-256 |

## AI 能替你做什么 {#ai}
- 本页**没有开放任何 AI 工具**：AI 不能检查更新、下载、安装或重启，也读不到当前版本与检查结果。
- 推荐问法：「怎么更新到最新版」——AI 给出的是到本页操作的指引。
- **做不到**：不代下载、不代装、不代重启；「安装并重启」必须由你点击确认。

## 常见失败与处置 {#errors}

| 界面提示 | 原因 | 处置 |
|---|---|---|
| 检查更新失败：网络不可用… | GitHub / Gitee 都不通，或代理拦截 | 确认能访问 gitee.com 后重试；国内优先看 Gitee 镜像 |
| 检查更新失败：GitHub 接口限流… | 匿名 API 每小时 60 次被用完 | 稍后再试；应用会优先读 Gitee 的 `update.json`，不依赖 GitHub API |
| 该版本没有可用的单文件更新包 | 发布里只有压缩包，或清单里没有下载源 | 点「打开发布页」手动下载 |
| 文件校验失败（SHA-256 不匹配） | 下载被截断 / 代理改写 / 发布信息对不上 / 分片顺序错 | 已自动删除坏文件，重新点「下载」；反复失败请去镜像页手动下载 |
| 下载失败，请检查网络后重试 | Gitee 与 GitHub 源都失败（超时、403、分片 404 等） | 换网络后重试；应用会自动尝试下一个下载源 |
| 程序所在目录不可写 | 程序放在 Program Files 等受保护目录 | 把整个程序目录移到用户可写位置后重试，或手动覆盖 exe |
| 当前运行方式不支持自动替换 | 通过 `dotnet` 宿主/调试器启动，不是单文件 exe | 使用发布出来的 exe 运行；开发调试时不上自动更新 |
| 替换 exe 失败，旧版本已保留 | 安全软件拦截 / 文件被占用 | 关闭安全软件拦截后重试；必要时手动覆盖 |

## 限制与已知问题 {#limits}
- **只支持单文件 exe**：这是绿色版发布形态决定的。压缩包 / 安装器 / 多文件目录不在自动更新范围内。
- **Gitee 只能放分片**：免费账号单个发行版附件不能超过 100 MB，应用需要下载多个分片后拼接；分片数量越多，首次更新越慢。
- **整包下载，没有增量更新**：每次下载完整的 exe（约 130 MB 级），首次启动还要解压到临时目录。
- **没有代码签名**：未做数字签名，SmartScreen 可能提示未知发布者；更新包本身通过 SHA-256（发布方提供时）与 PE 头校验，但不能替代签名。
- **旧版本的临时解压目录不会立即清理**：单文件运行时内容解压在 `%TEMP%\.net\TheGuideToTheNewEden\<hash>\`，换版本后旧目录仍在，系统清理临时目录时会回收。
- **版本比较是语义化的**：预发布之间按 SemVer 规则比较；如果发布方把更新的版本标成 GitHub 的 prerelease，`releases/latest` 不会返回它，需要手动到发布页下载。
- **更新失败不会破坏旧版本**：先备份再替换；就地替换失败会回滚，兜底脚本替换失败会把旧 exe 放回。
- **Gitee 清单来自仓库根目录的 `update.json`**：仓库默认分支需为 `master` 或 `main`；仓库改名/默认分支变化后，应用会回退 GitHub 源。
