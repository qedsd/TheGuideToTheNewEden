# 设置 · 测试

## 一句话 {#tldr}
三项环境自检：发一条测试通知、放一段声音、检测浏览器授权回调的本地监听地址——排查"通知不弹、没声音、添加角色卡在授权"时用。

## 在哪打开 {#where}
- 左侧导航「**设置**」→ 分类列表「**测试**」（说明文案：「测试系统通知、声音播放」）。
- 页面是四张设置卡片：**系统通知**、**声音播放**、**回环回调**（检测 / 复制）与**回环回调**（地址显示）。
- 也可在主页「添加功能」窗口里把「设置 · 测试」加成磁贴，点了直达本页。

## 操作步骤 {#steps}

### 测系统通知
1. 点「**发送通知**」→ 用当前通知通道发出一条测试通知（标题「测试」）；通道异常时会弹窗显示具体错误。
2. 点「**检测环境**」→ 弹窗「**系统通知检测结果**」给出两种结论之一：「**应用通知已启用**」或「**应用通知不支持**」。
3. 通知发了但屏幕上看不见：先看右下角 / 系统通知中心，再确认系统没开勿扰；得到「应用通知不支持」说明通知通道本身不可用（常见于从受限目录运行，托盘图标被系统拒绝创建）。

### 测声音播放
1. 点「**播放**」→ 播放内置的默认声音；播放失败会弹窗显示错误。
2. 点「**选择声音文件**」→ 选一个 `mp3 / wav / wma` 文件，弹窗回显所选路径；之后「播放」改放你选的文件。
3. 点「**暂停**」→ 暂停当前播放。

### 测回环回调（授权回调地址）
1. 卡片默认显示**当前配置的回调地址**（未配置时显示建议地址 `http://localhost:38471/callback/`）。
2. 点「**复制**」→ 地址进剪贴板，显示「已复制到剪贴板」——贴到 EVE 开发者后台该 SSO 应用的 Callback URL 即可。
3. 点「**检测**」→ 校验配置并**真实监听一次端口**：成功显示「**监听成功**」+ 地址；配置有问题显示 ✗ 与具体原因；端口起不来显示地址与错误。
4. 这条链路要求**三处一致**：当前回调地址（发布版内置于程序；开发/覆盖时来自 `Configs/ESILicense.txt` 第 2 行）= EVE 开发者后台登记的 Callback URL = 本机该端口可用。改任一处都要同步改另一处，且回调地址**不支持通配端口**。
5. 用途：欧服「**添加角色**」时浏览器授权完跳回本进程的入口。检测通过只证明"当时这个端口能收到回调"，不代表授权流程全程无阻。

## AI 能替你做什么 {#ai}
- 本页**没有开放任何 AI 工具**：AI 不能替你发测试通知、放声音，也不能替你执行回环回调检测或读取检测结果。
- 授权回调配置同样没有工具：AI 只能指引你到本页检测、去开发者后台核对 Callback URL。
- 推荐问法：「添加角色时浏览器没跳回来怎么办」——AI 给排查思路，检测要你亲自点。

## 常见失败与处置 {#errors}

| 界面提示 / 现象 | 原因 | 处置 |
|---|---|---|
| 应用通知不支持 | 通知通道不可用：托盘图标没创建成功（受限目录运行时进程完整性过低，会被系统拒绝） | 从普通安装位置运行应用（不要放在受限工作区里跑）后再测 |
| 发送通知没出现 | 通知被系统设置 / 勿扰拦截，或通道不可用 | 先「检测环境」看结论；再检查系统通知设置 |
| 回环回调显示 ✗ + 原因 | 配置地址与开发者后台登记不一致、地址非法或端口被占用 | 按提示让开发者后台与当前回调地址（发布内置或 `Configs/ESILicense.txt` 第 2 行）一致；终端用户改不了内置值，需联系发布者；端口被占用稍后重试（检测会真实占用一次端口） |
| 播放报错弹窗 | 声音文件损坏或解码失败 | 换一个 mp3 / wav 文件再试 |

## 限制与已知问题 {#limits}
- **「检测环境」只给两种结论**：应用通知已启用 / 应用通知不支持；不细分系统设置里的具体拦截原因。
- **回环检测是即时占用**：只证明检测那一刻端口能监听，不等于之后的真实授权一定成功（后台登记与当前回调地址两处仍须一致；发布版地址已内置，开发/覆盖时才看 `ESILicense.txt`）。
- **回环地址不支持通配端口**：回调地址必须与 EVE 开发者后台登记的完全一致（含端口），这是平台限制（REFACTORING 阶段 51）。
- **旧的注册表协议卡片已删除**（REFACTORING 阶段 52）：本页不再有「HKCR 协议」相关内容，授权回调只走本地回环，不要按旧资料配置自定义协议。
