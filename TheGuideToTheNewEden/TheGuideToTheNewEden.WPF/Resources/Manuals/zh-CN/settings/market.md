# 设置 · 市场

## 一句话 {#tldr}
调整市场取数的**缓存有效期、ESI查询线程数**与"是否跳过公开建筑订单"，并一键清除本地订单 / 历史缓存。改完**立即生效**，本页没有「保存」按钮。

## 在哪打开 {#where}
- 左侧导航「**设置**」→ 分类列表里的「**市场**」（副标题「缓存时间、查询线程、清除缓存」）→ 进入子页；页内标题与面包屑第二段都显示「市场」，点面包屑里的「设置」返回分类列表。
- 子页是一列设置卡片，自上而下六项：**订单有效时长** / **历史记录有效时长** / **ESI查询线程数** / **倒货跳过公开建筑订单** / **市场跳过公开建筑订单** / **清除缓存**。
- 控件形态：前三个是带内嵌步进按钮的数字框（最小 1，步进 1；两个时长框右侧带单位「m」= 分钟）；两个"跳过"项是开关；清除缓存是按钮「**清除**」。

## 前置条件 {#prereq}
- **不需要登录角色**：星域 / 星系取数走匿名接口，这里的缓存与线程设置对所有市场生效。
- **建筑（结构）市场本身**的授权与「设置 → 玩家建筑」有关（需要角色对该建筑有市场访问权），与本页设置无关。
- 清除缓存要删**数据目录**下 `Configs` 里的缓存文件（默认 `%LocalAppData%\TheGuideToTheNewEden\V4\Configs`；主页「打开配置目录」即指向这里），运行位置需要对它有**写权限**；受限位置（低完整性、只读目录）下删除可能失败，而界面不会单独报错——同理，这里改的设置值写不进去时也是静默的，不会弹提示。

## 操作步骤 {#steps}

### 改一个值
1. 「设置 → 市场」，找到目标卡片。
2. 在数字框里直接输入，或点内嵌的上下箭头按 1 增减（最小 1）。
3. 改完即生效：立即写入设置，影响**之后**的取数判断。已经写下的缓存文件不会被重写，只是按新的有效期重新判定"还算不算新鲜"。
   - 例：把「订单有效时长」从默认值调小后，先前写下的建筑 / 整星域缓存马上就变成过期，下次取数会重新走 ESI（更慢，但更新）。

### 让取数更快
1. 慢在"每次都重新拉" → 把「订单有效时长」「历史记录有效时长」**调大**，重复查询会命中磁盘缓存。
2. 慢在"要拉很多页 / 很多物品" → 微调「ESI查询线程数」（默认 4）。界面说明是「理论上越大越快，但过快会触发ESI请求限制」。

### 切换跳过公开建筑订单
1. 「倒货跳过公开建筑订单」默认**开**：倒货（含 AI 的倒货分析）取星域 / 星系市场订单时，不再额外获取公开建筑的订单，整星域取数明显更快，代价是少了只在这些建筑里挂单的部分。
2. 关掉后，倒货取数会再把这些建筑的订单合并进来；每个建筑都要整栋拉一次，首次会非常慢。改动同时影响倒货页与 AI 的倒货分析。
3. 「市场跳过公开建筑订单」的说明文字写的是"市场（包括频道市场）"，但当前市场页的星域 / 星系取数本来就不合并建筑订单，因此开 / 关在市场里看不出差别（见「限制与已知问题」）。

### 清除缓存
1. 点「**清除**」→ **没有二次确认**，直接删掉建筑订单、星域订单、历史记录三类缓存目录。
2. 随后弹出提示框「**已清除缓存订单信息**」（标题「市场」）。
3. 之后首次取数会全部重新走 ESI（明显变慢）。数据看起来是旧的、或改完缓存时长仍想立刻重取时，这是最直接的手段。

## 字段与口径 {#fields}

| 设置项 | 默认值 | 取值 / 单位 | 影响（口径） |
|---|---|---|---|
| 订单有效时长 | 60 | ≥1，右侧单位「m」（分钟） | 订单类磁盘缓存的有效期：**建筑市场的整栋订单**、**整星域订单**（倒货与 AI 倒货分析整星域取数）。未过期直接读缓存 |
| 历史记录有效时长 | 60 | ≥1，单位「m」 | 历史统计缓存的有效期：市场页「历史」页签与走势、估价 / 倒货、频道查价、主页行情卡、AI 的市场历史类工具（比价只看实时订单，不读历史缓存） |
| ESI查询线程数 | 4 | ≥1，纯数字 | 订单分页取数与批量历史取数的并发度；界面说明「理论上越大越快，但过快会触发ESI请求限制」。市场 / 倒货 / 估价 / 比价共用同一个值 |
| 倒货跳过公开建筑订单 | 开 | 开 / 关 | 开 = 倒货获取星域 / 星系市场订单时，不获取公开的建筑订单 |
| 市场跳过公开建筑订单 | 开 | 开 / 关 | 说明文字：市场（包括频道市场）获取星域 / 星系市场订单时，不获取公开的建筑订单 |
| 清除缓存 | — | 按钮「清除」 | 删除建筑订单、星域订单、历史记录三类缓存；不删除角色授权、玩家建筑列表等设置 |

口径补充：
- **未过期的缓存直接返回**：两个"有效期"决定的是"多久之后才重新问 ESI"，不是"数据本身有多新"；调大更省更快，代价是可能看到旧一档的订单。
- 三个数字框**只限制最小值 1，没有上限校验**：填很大的值不会被拦下。线程数另有一条边界——**订单翻页的并发内部封顶**（填得再大也只按封顶值跑），批量历史取数则按设置值并发，过大不会更快、只会更容易触发 ESI 请求限制。
- 两个"跳过"开关是**独立**的：倒货只看「倒货跳过公开建筑订单」，市场侧的说明写在「市场跳过公开建筑订单」上，互不联动。

## AI 能替你做什么 {#ai}
- **可以读写这些设置项**：`config_read`（name=`settings`）读 `settings.json` 里的 `OrderDuration` / `HistoryDuration` / `Thread` / `ScalperSikpStructure` / `MarketSikpStructure` 等键，`config_write` 只能改已存在的非密钥键；写入需确认、旧内容自动备份、可用 `config_restore` 回滚。改完可用 `feature_restart`（name=`settings`）重读。
- AI 能读到 / 间接用到这里的设置：`scalper_settings`（只读，**无需确认**）会报出源市场、目的市场、目标物品数与**取数线程数**；`market_history`、`market_trend` 的历史统计走本页「历史记录有效时长」缓存；`market_orders`（以及 `market_trend` 的现价）是实时订单、**不读本页缓存**；`scalper_analyse` 与倒货页共用「倒货跳过公开建筑订单」的口径。
- 推荐问法：「现在的 ESI 查询线程数是多少」「倒货现在是什么配置」「为什么第一次查历史很慢」「清完缓存要等多久才出数据」。
- **做不到**：替你点「清除」清缓存（配置文件工具不删缓存目录）；AI 的 ESI 全量网关取数也**不经过本页缓存**（网关有自己的一套页数与配额口径，见「设置 → AI」的 ESI 全量访问一节）。

## 常见失败与处置 {#errors}
本页**没有输入校验报错**：数字框最小值为 1，开关与按钮都是点一下就生效；唯一会弹出的提示是清除缓存后的「已清除缓存订单信息」。

| 现象 | 可能原因 | 处置 |
|---|---|---|
| 点「清除」后仍看到旧订单 / 旧历史 | 缓存目录被占用或当前运行位置没有写权限，删除没有成功（界面不会有单独报错） | 退出应用后重试；或到配置目录的 `Configs/StructureOrders`、`Configs/RegionOrders`、`Configs/HistoryOrders` 手动删除 |
| 改完缓存时长后，数据看起来还是旧的 | 缓存按"有效期"判定，未过期就直接读缓存 | 点「清除」重来；或把对应的有效期（订单 / 历史）调小，让旧缓存立刻失效 |
| 清除后第一次查询特别慢 | 缓存已空，全部重新走 ESI | 属预期；等这次查询写入缓存后就会恢复 |
| 线程数调大后没有更快，甚至更容易失败 | 订单翻页的并发内部封顶（设置填得再大也不生效）；批量历史取数并发过高会触发 ESI 请求限制（界面说明已提示） | 调回较小值（如默认 4 附近）再试 |

## 限制与已知问题 {#limits}
- **单物品的星域订单不受本页缓存时长影响**（REFACTORING §8-13）：市场页查单个物品的星域 / 星系订单走 ESI 实时、没有缓存；这里的两个时长作用于建筑订单、整星域订单与历史统计。清缓存也不会让实时查询变快。
- **建筑（结构）市场**（REFACTORING §8-9）：建筑订单是**整栋全量**拉取、按「订单有效时长」缓存，首次明显较慢；需要角色授权，失败时页面给提示；"建筑历史"其实是**该建筑所在星域**的历史。
- **「市场跳过公开建筑订单」目前看不出差别**（REFACTORING §8「计划内未做」）：星域 / 星系市场取数恒按"跳过结构"处理，不会把星域内建筑的订单合并进来，所以这个开关开 / 关对市场结果没有可见影响；会因此变化的取数是倒货。
- **本页没有「保存」也没有「恢复默认」**：所有改动即时写入，误改只能自己改回；三个数字框只限制最小值为 1，没有上限校验。
- **市场页取数没有全局进度提示**：市场 / 订单等页是静默加载 + 页内文字提示（等待遮罩与应用内通知接在别的页面上）；清缓存或调小有效期后的首次取数只表现为"慢"。
- **清除的提示与实际可能不一致**：个别缓存目录删除失败时界面仍会弹「已清除缓存订单信息」（失败只进日志），所以清完仍见旧数据时请按上面的处置手动确认。
- **整星域缓存是大文件**（REFACTORING 阶段 29 记录为百 MB 量级）：清除它本身需要一点时间。
- **设置文件与旧版共用**（REFACTORING §8 环境/协作注意）：`Configs/settings.json` 与 WinUI 版共用，两版同时运行会互相覆盖，建议只保留一版运行。
